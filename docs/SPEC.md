# M5StickC Plus SE ミニゲーム集 実装仕様書

作成日：2026-10-03 / 仕様バージョン：1.0

## 1. 実装エージェントへの依頼

本書だけを読んで、M5StickC Plus SE向けの5種類のミニゲームを実装する。説明や設計だけで終了せず、ビルド可能なソースコード、設定、README、検証結果を納品する。実機が利用できない場合もビルドとゲームロジックの検証まで進め、実機未検証の事項を明記する。

下記のゲーム採用・一般向けテーマ・追加機材なしはユーザー決定事項。それ以外の数値や操作は実装を進めるための初期仕様であり、実機で遊びやすくなる範囲で調整可能。変更した値と理由はREADMEに残す。

## 2. 目的と対象範囲

展示会場で来場者が端末を手に取り、短時間で遊べる小型ミニゲーム集を作る。画面が小さいため、1画面の主役を1つに絞り、大きな絵と短い文字で理解できるようにする。

採用ゲーム：
1. ホームラン競争
2. チキン風船
3. 記憶スイッチ
4. 声で浮く気球
5. ぴったり10秒

一般向けの独自デザインとする。任天堂作品は遊び方の参考にとどめ、キャラクター・画像・音源は使用しない。外付けセンサー、発信機、スマートフォン、サーバー、Wi-Fi接続は必要としない。歩数計、育成、ダウジング、アイテム図鑑・抽選は今回のMVPに含めない。これらは過去に検討した案であり、今回の確定仕様ではない。

## 3. ハードウェアと技術方針

- 対象は **M5StickC Plus SE（K016-P-SE）**。Plus、Plus2、StickS3と混同しない。
- ESP32-PICO-D4、Flash 4MB、SRAM 520KB。
- 画面は135×240。アプリでは横向き240×135を基本とする。正面Aボタンと側面Bボタンが押しやすい回転方向を実機で選び、READMEに向きを図示または文章で説明する。
- 操作はA・Bの2ボタン。電源ボタンをゲーム操作に使わない。
- 内蔵マイクあり。加速度・ジャイロ・タッチ操作は使用しない。
- 内蔵ブザーは短い電子音用。音声再生用スピーカーとして扱わない。
- USB給電展示を基本にする。バッテリー駆動時間は実測なしで保証しない。
- C++ / Arduinoフレームワーク、PlatformIOを第一候補とする。M5UnifiedとM5GFXを用いる。
- SE公式Factoryリポジトリと公式ドキュメントの設定・初期化を確認し、SE対応を検証したバージョンを固定する。未確認のboard IDや旧ライブラリ互換性を推測して設定しない。
- アニメーションはM5Canvas等で画面をメモリ上に描いて転送し、ちらつきを抑える。まず30fpsを目標にし、60fpsは必須にしない。
- 固定サイズ配列、起動時に確保したバッファを優先。毎フレームの動的メモリ確保を避ける。
- millis等の単調増加時計で時間を管理し、長いdelayで入力・描画を止めない。経過時間の計算はカウンタのラップを考慮する。

## 4. 共通UI・入力

### 4.1 画面遷移

起動 → ゲーム選択 → 操作説明 → カウントダウン → プレイ → 結果。

- ゲーム選択：1画面に1ゲームの大きなアイコン、名前、自己ベスト、現在の番号（例：2/5）。A短押しで次、B短押しで決定。5本の後に「設定」を置く。
- 操作説明：絵と1〜2行の説明、Aで開始、Bで選択画面に戻る。
- カウントダウン：3・2・1を各0.5秒表示。ゲーム入力を受け付けない。
- 結果：今回の記録、自己ベスト、更新時にNEW表示。Aで再挑戦、Bで選択画面へ。
- プレイ中：A+Bを両方800ms保持すると中断して選択画面へ戻る。中断は記録保存しない。
- メニュー・説明・結果で30秒無操作ならゲーム選択画面へ戻る。プレイ中には適用しない。
- 遷移後は両ボタンが離されるまで次画面の入力を無効にし、押しっぱなしの誤開始を防ぐ。

### 4.2 ボタン処理

- デバウンス済みの押下・解放・保持イベントを共通Input層で生成する。
- 短押し操作は解放時に確定する。長押し・同時押しが成立した場合、短押しを後から発火しない。
- A+B中断の検出を優先し、両方を押している間はゲーム操作を抑止する。
- ゲーム内で別途明記した「押下」「保持」はそのイベントを使用する。

### 4.3 表示・音

- 背景と主役のコントラストを高くする。重要な数字は24px以上を目安とする。
- 日本語フォントは必要な字形のみを埋め込む等で容量を管理。既存フォントを使う場合はライセンスを確認する。
- 表示が収まらない場合も極端に小さくせず、短い表現にする。
- 色だけに依存せず、形・文字でも状態を区別する。
- ブザーは開始、成功、失敗、ベスト更新で短い効果音。設定でOFF可能。
- 声で浮く気球のマイク校正中・プレイ中はブザーを鳴らさず、自己音の混入を避ける。

## 5. 各ゲーム

### 5.1 ホームラン競争

目的：10球の合計得点を最大化する。

- 横向き画面の左側に打者、右から左へ球が飛ぶ。バットの位置を打撃基準点として明確に描く。
- 2026-10-03の追加要望により、10球制と判定幅を維持し、後半ほど速い4段階の投球に変更する。各球の開始時に待機時間・飛行時間を決定し、到達時刻を確定する。

  | 球数 | レベル | 投球前の待機 | 基準点までの飛行 |
  | --- | --- | --- | --- |
  | 1〜3球目 | Lv1 | 500〜900ms | 900〜1100ms |
  | 4〜6球目 | Lv2 | 400〜1000ms | 700〜850ms |
  | 7〜9球目 | Lv3 | 300〜1100ms | 550〜650ms |
  | 10球目 | Lv4 | 300〜1100ms | 450〜500ms |

- 各範囲の整数ミリ秒から一様乱数で選ぶ。レベルが変わる球は、直前のレベルのどの球よりも必ず速くなる。同じレベル内の速度と待機時間は変化させる。
- 球の描画と判定は同じ飛行時間・到達時刻を使用する。球数・合計点・現在レベルを表示する。再挑戦はLv1・1球目・0点から始める。
- A押下でスイング。1球につき1回だけ有効。早すぎるスイングも空振りとして消費する。
- 押下時刻と球の基準点到達時刻との差の絶対値で判定する。
  - 50ms以内：ホームラン、100点。
  - 100ms以内：ヒット、50点。
  - 150ms以内：かすり、20点。
  - それ以外／到達後150msまで入力なし：空振り、0点。
- 成功・失敗を0.6秒表示して次の球へ。球数と合計点を表示する。
- 最大1000点、高い値を自己ベストとする。
- 描画フレーム数ではなく入力時刻で判定する。1球に複数回加点されないこと。

### 5.2 チキン風船

目的：割れる手前まで風船を膨らませ、高得点で確定する。

- 1プレイ1風船、制限時間15秒。
- A短押しで1段階膨らませる。保持による連続加算なし。1段階10点。
- 開始時に破裂段階を12〜24の一様乱数で決定し、プレイヤーには見せない。
- 段階が破裂段階に達した瞬間に破裂し、今回の得点は0点。
- B短押しで現在の得点を確定。時間切れも同じく現在点で確定する。
- 膨張率に応じて風船を大きくし、危険域では揺れや表情を加える。危険域の演出は破裂段階の約70%・90%を基準にしてよいが、正確な残り回数は表示しない。
- 高い得点を自己ベストとする。破裂段階・乱数seedを固定できる開発モードを設ける。

### 5.3 記憶スイッチ

目的：A・Bの順番を覚え、何段階まで正しく入力できるか競う。

- レベル1は長さ2。成功ごとに1個追加、最大長12。
- 同一プレイでは前の列に1つ追加する。A/Bはそれぞれ50%で生成する。
- 各記号を450ms表示し、150msの空白を挟む。画面上でAとBを形や位置でも区別する。
- 列の提示中は入力禁止。提示後、ボタン解放を待って入力フェーズ開始。
- 入力は短押し。押すたびに何番目まで入力したか表示するが、正解列は表示しない。
- 1入力あたり3秒以内。誤入力または時間切れで終了。
- 得点は最後に完全正解した列の長さ。初回失敗は0。
- 長さ12を正解したらPERFECTで終了。高い値を自己ベストとする。

### 5.4 声で浮く気球

目的：音量で気球の高さを操作し、時間制限なしで障害物を避けて生存時間の自己ベストを伸ばす。

2026-10-03の追加要望により、20秒制限を撤廃し、配置と段階的な難易度上昇を変更。

- 左側に気球、右から上下に開口のある障害物が流れる。画面全体の音量波形は不要。小さな音量ゲージを表示する。
- 操作説明の後にマイク校正を行い、その後カウントダウンへ進む。
- 校正：周囲の音を2秒測る → 「あー、と声を出して」2秒測る。必要ならBでやり直せる。
- 基本入力は短いフレームのPCMから計算した音量（DC平均を除いたRMS）。16kHz、256サンプル程度を初期値とし、公式マイクAPIの制約に合わせて調整する。
- 環境音の基準と発声音の基準の差から0〜1へ正規化し、指数平滑化（初期値alpha=0.2）する。大声そのものを競うゲームにしない。
- 校正値の差が小さすぎる／マイク取得失敗なら再校正かボタンモードを選べるようにし、ゼロ除算や永久待機を防ぐ。
- 音量0では下降、0.5付近ではほぼ静止、1では上昇する。速度の初期値は v_y=45-100*level [px/s]（下向き正）。dtで位置を更新する。
- 上下端では位置を制限し、端に触れるだけでは即ゲームオーバーにしない。
- 初期は出現間隔2秒、横速度60px/s、開口幅48px。10秒ごとに速度を10px/s増加、間隔を0.1秒短縮、開口を3px縮小。60秒でLv7（120px/s、1.4秒間隔、30px開口）に達し、以後この難度を維持する。
- 開口は上側・下側を交互に狙い、0〜3pxの乱数で変化させる。隣の開口中心の移動量は最大26pxに制限する。初期位置は中央、最初の出現は2秒後。
- 開口幅は生成時に固定する。画面上の障害物がレベル変更で突然狭くならない。横速度は全障害物に共通の現在レベルを適用する。
- 障害物との接触で終了。表示形状に合わせたやや小さめの当たり判定を使う。
- 得点は生存時間を0.1秒単位で整数化した値。20秒を超えても終了せず、衝突まで続く。結果画面は秒表示。高い値を自己ベストとする。旧版の記録・設定もそのまま読み込める。
- **ボタン代替モード必須**：A保持で上昇、離すと下降。マイク失敗時でも遊べる。結果・自己ベストは音声／ボタンを別に保存する。
- 設定で音声／ボタンの既定モードを選べる。記録画面にも使用モードを表示する。

### 5.5 ぴったり10秒

目的：10秒との誤差を最小化する。

- 共通カウントダウン後にREADY画面。A押下で計測開始。開始に使った押下では停止させず、一度離した後の次のA押下で停止する。
- 最初の2秒は経過時間を表示。その後は「？」と静止した時計アイコンに変える。
- 時間を推測できる定期的なアニメーションやブザーを、時計が隠れた後に出さない。
- 20秒で自動終了しTIME OUT。タイムアウトは自己ベスト対象外。
- 記録は計測時間とabs(計測時間-10000ms)。計測は整数ms、画面表示は小数2桁の秒。
- 自己ベストは最小の絶対誤差。初回未記録は「--」。完全一致の0msを未記録扱いしない。

## 6. 設定と保存

- 設定項目：効果音ON/OFF、明るさ3段階、気球の既定入力モード、気球の再校正、全記録リセット。
- 設定ではAで項目送り、Bで変更。末尾に「戻る」を置く。
- 記録リセットは確認画面を出し、Aで取消、Bを2秒保持で確定する。
- ESP32 Preferences/NVS等へ、schemaVersion、ゲーム別自己ベスト、ベスト有無、気球のモード別ベスト、設定を保存する。
- ベスト更新時と設定変更時のみ書く。毎フレーム・毎入力でFlashへ書き込まない。
- 校正値は会場状況に依存するため起動をまたいで流用せず、同じ起動内でも各音声プレイ前に校正する。
- 保存領域未初期化・不正値・旧schemaでは安全な初期値にする。読込・保存エラーでもゲームは続けられるようにする。

## 7. 実装構成

以下は責務の例。ファイル名の一致は必須ではない。

```
platformio.ini
src/main.cpp
src/app/          # 画面遷移、共通メニュー、結果
src/platform/     # M5初期化、入力、描画、ブザー、マイク、保存
src/games/        # 5本のゲーム状態・更新・描画
include/          # 共通定義、調整パラメータ
test/             # ハードウェア非依存のロジック検証
README.md
THIRD_PARTY_NOTICES.md
```

- ゲーム共通のenter/update/render/exitと結果データを用意する。
- Inputに押下・解放・保持、Micに0〜1の音量と取得状態を渡し、ゲームロジックをハードウェアから分離する。
- 乱数・時計を差し替えられる構造にし、境界判定を再現可能にする。
- マイク取得は短い非同期取得または専用タスク等で行い、描画・入力を長時間待たせない。バッファの所有と同期を明確にする。
- UIからゲームを抜けたらマイク取得とゲーム固有の効果音を停止し、再入場時に状態を初期化する。
- 横画面のゲーム領域と上部スコア領域、下部操作領域を共通化し、文字とプレイ領域が重ならないようにする。

## 9. 実装順序

1. SEでビルドできる最小プロジェクトを用意し、画面・A/B・ブザー・マイク入力を個別確認。
2. 共通入力、画面遷移、Canvas描画、保存を実装。
3. ぴったり10秒 → ホームラン → 記憶スイッチ → チキン風船。
4. 気球のボタンモードを先に完成し、マイク校正・音量入力を接続。
5. 結果・自己ベスト・設定・中断操作を統合。
6. 実機で見やすさ、側面ボタンの押しやすさ、会場騒音への反応を調整。

## 10. 受け入れ条件・検証

### ソフトウェア

- README記載の手順でビルドでき、使用ライブラリとツールチェーンのバージョンが明確。
- 5ゲームが選択・開始・終了・再挑戦できる。
- 10秒計測、ホームラン判定の50/100/150ms境界、風船破裂境界、記憶列の正誤・タイムアウト、気球の衝突をハードウェア非依存で検証する。
- マイク校正失敗・サンプル取得失敗・ボタン代替モードを検証する。
- 気球の音声とボタンで記録が混ざらず、10秒ゲームの0ms誤差を保存できる。
- 入力持ち越し・同時押し中断・設定リセットで誤操作しない。
- 実際に行った検証と未検証を区別して報告する。

### 実機（実機なしの場合はチェックリストとして納品）

- 横画面で字と絵が切れず、ゲーム説明と結果が読める。
- 長押しで意図しない連打や二重開始が起きない。
- 電源再投入後も自己ベスト・設定が保持される。
- USB給電で20分以上、ゲーム切り替えと再挑戦を繰り返してフリーズ・明らかなメモリ減少・音声入力停止がない。
- 静かな場所と人の会話がある場所で音声モードを確認。校正後に小さな声でも操作できるか、周囲の音だけで常時上昇しないかを確認。
- 雑音で遊びにくい場合は入力モード切り替えでボタン版を遊べる。
